#### What is better? Virtual Machines vs Docker

The choice between a virtual machine and Docker always depends on the user’s goal.  
Some tasks are easier to accomplish with Docker containers, but in other cases a VM is required.  
For example, if you need to test programs or host processes (as in this project), a VM is preferable.  
When automating processes, Docker is often easier and faster.  
Determine your goal and choose accordingly.

#### Secrets vs Environment Variables

The difference is simple:  
   * Secrets are for human consumption.  
   * Environment variables are for programmatic use.  

Configuration files can retrieve information from environment variables to automatically configure settings in Docker containers.

#### Docker Network vs Host Network

The default Docker network is **bridge**, which I used in this project.  
Containers attached to the bridge network can access network services outside the Docker host via masquerading.  
If the Docker host has internet access, no additional configuration is needed for containers to reach the internet.  
This is the easiest and most reliable networking option for the Inception project.

The host network removes network isolation between the container and the Docker host.

#### Docker Volumes vs Bind Mounts

Volumes are persistent data stores for containers, created and managed by Docker.  
They are the preferred mechanism for persisting data generated by and used by Docker containers.  
Bind mounts depend on the directory structure and OS of the host machine, while volumes are completely managed by Docker.  
Volumes are easier to back up or migrate than bind mounts, and can be managed with Docker CLI commands or the Docker API.
